# Tessera Production-Hardening Audit (2026-07-29)

This is the audit that the user (sole architect) commissioned in response to
the drafter 0.86% accept rate on tessera Q4_K_M. The finding was that the
requantization algorithm wasn't calibrated for the bulk of the network —
the global `ternary_threshold = mean(|W|)` default caused 70-150% per-layer
output error at layers 4, 8, 16, 32. Before adding the missing calibration
knob (per-tensor `ternary_threshold` in the GA), the user asked: are the
existing tessera additions to llama.cpp held to the same production-quality
bar as the rest of the llama.cpp code? The answer was "no, several pieces
are workarounds" — and the audit's purpose is to enumerate them so each
piece can be hardened.

## Concrete findings

### 1. `common/arg.cpp` — duplicate flag registration (real bug)

`--telemetry-out` and `--telemetry-topk` are each registered twice
(lines 1643-1667 and 1679-1703 before the fix). The two `add_opt` blocks
were byte-identical, a copy-paste merge bug. **Fixed 2026-07-29** by
removing the duplicate registrations.

### 2. `common/speculative.cpp` — `mtp_context()` and `ane_mtp_program()` are stubbed

The header declares these as production API but the bodies explicitly
return `nullptr`:

```cpp
// Recovered from 9e9f275. The current `impl` struct doesn't carry separate
// `context_mtp` or `ane_mtp` members (the WIP commit 06e514f didn't complete
// the MTP context wiring), so both accessors return nullptr.
llama_context * common_speculative_init_result::mtp_context() {
    return nullptr;
}
void * common_speculative_init_result::ane_mtp_program() {
    return nullptr;
}
```

`server-context.cpp` uses these to wire MTP, but since they always return
`nullptr`, the MTP path is silently no-op. This is the root cause of the
loading issue on gemma 4 12B F16 with MTP — the auto-MTP triggers but
the path doesn't work. **Mitigated** via the `--no-embedded-mtp` flag
(added 2026-07-29), but the MTP path itself needs to be implemented
properly or the auto-trigger needs to be removed.

### 3. `src/llama-graph.cpp` — `dft.` string prefix is a workaround

`imatrix_observer_name()` returns `"dft." + weight_name` for
`LLM_ARCH_DFLASH`, applied at 4 call sites (lines 1438, 1471, 1625, 1655,
2147). The proper way to handle verifier/drafter separation is two
distinct observer maps or per-context observer state. `is_drafter_arch()`
only checks `arch == LLM_ARCH_DFLASH` — it doesn't know about future
drafter types.

**To be fixed** by replacing the string prefix with per-context observer
state managed in `llama_context` and exposed via the C API as
`llama_set_imatrix_observer_filter` (already exists) plus a new
`llama_set_imatrix_observer_scope(ctx, scope)` that names which model
context the observer belongs to (verifier / drafter / etc.).

### 4. `tools/imatrix/imatrix.cpp` — bypasses `common_speculative_*`

1,536 insertions of manual drafter forward + KV rollback that bypass the
public `common_speculative_*` API. The 9e9f275 commit message says
"bypasses common_speculative_* due to off-by-one KV bugs" — the hack is
documented in the commit but still a hack. **To be fixed** by either:
(a) fixing the off-by-one bugs in `common_speculative_*` and using the
public API from `imatrix.cpp`, or (b) extracting the manual forward into
`common/speculative-calibration.{h,cpp}` as a properly-named API with
documentation explaining why it bypasses the public one.

### 5. Two parallel telemetry schemas

v1 (`llama.dflash.acceptance.v1`) and v2 (`llama.spec_calib.v2`) coexist
with two distinct emission paths in `imatrix.cpp` (lines 2347-2348). A
production-quality API would either deprecate v1 or unify them under a
single schema-versioned emission. **To be fixed** by unifying into
`llama.spec_calib.v3` with v1 as a documented adapter.

### 6. `tools/server/server-context.cpp` — auto-MTP triggers a broken path

Auto-sets `params.speculative.types = {COMMON_SPECULATIVE_TYPE_DRAFT_MTP}`
whenever the GGUF has `mtp.component.present = true`. Combined with the
nullptr stubs of `mtp_context()` and `ane_mtp_program()`, this auto-trigger
makes the server refuse to load any gemma 4 12B F16 with MTP. **Mitigated**
via `--no-embedded-mtp` (added 2026-07-29). **To be fixed** by either
properly implementing the MTP context path or removing the auto-trigger
and requiring explicit `--spec-draft-type mtp`.

### 7. `src/models/dflash.cpp` — DSpark fold is first-class, around it is workaround

- *First-class*: `LLM_ARCH_DFLASH` arch, `LLM_TENSOR_DSPARK_MARKOV_W1/W2/CONF_PROJ`
  tensor names, markov head graph — this is upstream PR #25173 done
  correctly.
- *Workaround*: gemma4-specific extras (lines 103-106) — `attn_post_norm`,
  `ffn_post_norm`, `rope_freqs`, `layer_output_scale` — are bolted onto
  the dflash loader with `TENSOR_NOT_REQUIRED` flags. **To be fixed** by
  extracting into `llama_model_dflash_gemma4` subclass.
- *Workaround*: legacy naming fallback (lines 46-56) — accepts
  `markov.w1.weight` AND `markov_w1.weight`. **To be removed** once the
  legacy converter is gone.
- *Workaround*: V required, MQA copy via preprocessor (lines 91-92).
  **To be removed** by fixing the original converter to emit V tensors.

### 8. `tools/dspark-gguf-patch/` — outright hack

`rewrite_dspark_gguf.py`: 163 lines of manual GGUF binary manipulation.
Hardcoded source/dest paths (`/Volumes/Julian T7/...`). 5 separate patches
documented in the README. `disable_swa.py`: 26 lines, also hardcoded
path, directly mutates binary `sliding_window` value with `struct.pack`.

**Will be removed** when the legacy converter is no longer in production
and the loader's legacy-naming fallback is gone.

### 9. Test coverage is shockingly thin

The whole spec-calib / drafter telemetry / MTP / dspark stack is 28,621
lines of code, and the only tests are:

- `tests/test-imatrix-observer-classification.cpp` (47 lines)
- `tests/test-imatrix-observer-epoch.cpp` (21 lines)
- `tests/test-ane-mtp.cpp` (245 lines)

**To be fixed** by adding tests for: dflash loader, dspark markov head,
telemetry JSON output, server-context auto-MTP, the patcher tools, the
tessera quantizer.

### 10. Documentation gaps

`tools/imatrix/README.md` has zero references to `--telemetry-out`,
`--telemetry-topk`, or `--spec-steps`. The new spec-calib feature is
completely undocumented in the user-facing README. **To be fixed** by
adding sections to `tools/imatrix/README.md` and `docs/speculative.md`.

### 11. Memory safety

`set_imatrix_observer_filter` at `llama-context.cpp:1147` doesn't
NULL-check `ctx` before dereferencing. **To be fixed** with proper
NULL guards.

### 12. Schema coupling between Python and C++

The `awq-evolve.py` Candidate dataclass and the
`tile640_quantize_v3.py` `tensor_policy()` function are coupled by JSON
schema with no validation step. **To be fixed** with a shared schema
definition (probably in `tessera/policy_schema.py`) and a validate-on-load
check in both ends.

## Verdict

The tessera additions are not currently first-class. The arg.cpp bug is
real, the auto-MTP regression is real, the dft. prefix and manual drafter
forward are workarounds that became structure, the test coverage is far
below the bar. Hardening is in progress via a coordinated set of agents
working in isolated worktrees; see `docs/architecture.md` for the merge
plan.

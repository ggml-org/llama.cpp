# P6.6b: fix GGML_SYCL_ENABLE_GRAPH crash on FA decode timing profile

2026-08-15. Fixes the crash found during the P6.6(b) unaccounted-decode-time probe
(`docs/research/round2-decode-probes-2026-08-13.md`): `GGML_SYCL_ENABLE_GRAPH=1` combined
with `GGML_SYCL_FA_PROFILE=1` crashed FLASH_ATTN_EXT on q8_0/q8_0 quants-first KV at deep
context. Default-off (`GGML_SYCL_ENABLE_GRAPH` defaults to 0), no production impact, but
blocked the probe and blocks any future graphs re-enablement work.

## Root cause

`launch_fattn()` (`ggml/src/ggml-sycl/fattn-common.hpp`) gates its q8 decode timing profile
on `ggml_sycl_fattn_profile_enabled() && Q->ne[1]==1 && K/V->type==Q8_0`. When that gate is
true it calls `main_stream->wait_and_throw()` four times to bracket conversion/stage1/combine
timings - unconditionally, with no awareness of whether the stream is currently being
recorded into a SYCL command graph. oneAPI forbids `wait()`/`wait_and_throw()` on a queue in
that state; the underlying UR/Level Zero runtime throws `sycl::exception` with message "wait
cannot be called for a queue which is recording to a command graph".

`ggml_backend_sycl_graph_compute()` (`ggml/src/ggml-sycl/ggml-sycl.cpp`) already has a
precedent for this exact hazard: `check_graph_compatibility()` disables graphs entirely for
`GGML_OP_CONCAT`/`GGML_OP_MUL_MAT_ID` because those ops do an unconditional blocking wait, and
the FA scratch-buffer pre-grow (`ggml_sycl_graph_prepare_fattn_buffers`) exists specifically to
move the *allocation*-triggered wait ahead of `begin_recording()`. The FA *profiling* wait was
the same hazard in a different call site, missed by both of those fixes because it only fires
when `GGML_SYCL_FA_PROFILE=1` is also set - a combination the graphs promotion campaign
(`docs/research/sycl-a770-p5-performance-campaign-2026-07-19.md`) never exercised.

The crash was a caught `sycl::exception` (logged, op returns `false`), not a process abort;
the visible symptom was `test_gen: failed to decode generation batch, res = -3` with an
already-corrupted queue, so the run failed rather than crashing outright. Confirmed reproducible
before this fix on Mistral-7B, q8_0/q8_0 quants-first KV, d=16384, with
`GGML_SYCL_FA_PROFILE=1 GGML_SYCL_GRAPH_PROFILE=1 GGML_SYCL_ENABLE_GRAPH=1`.

## Fix

- `ggml/src/ggml-sycl/common.hpp`: added `bool graph_recording = false;` to
  `ggml_backend_sycl_context`, unconditionally (not gated by `#ifdef GGML_SYCL_GRAPH`) so it is
  always a valid `false` default in builds without graph support.
- `ggml/src/ggml-sycl/ggml-sycl.cpp`: `ggml_backend_sycl_graph_compute()` wraps the
  compute/`end_recording()` call in a scoped RAII guard (`graph_recording_guard`, local struct)
  that sets `sycl_ctx->graph_recording = true` on construction (right after `begin_recording()`)
  and back to `false` on destruction. This resets the flag on every exit from that scope,
  including if `ggml_backend_sycl_graph_compute_impl()` or `end_recording()` throws - a plain
  `= true` / `= false` pair around the call would leave the flag stuck `true` on that path.
- `ggml/src/ggml-sycl/fattn-common.hpp`: the `profile` gate in `launch_fattn()` now also
  requires `!ctx.graph_recording`. This is a pure extension of the existing "profiling
  synchronizes the queue and is intentionally limited to q8 decode" scoping comment - during
  graph capture the profile is silently skipped (no timing data for that call), which is
  correct: the geometry counters (`GGML_SYCL_FA_GEOMETRY`, a separate always-on collector) are
  unaffected and still report.

Full audit of the other `wait()`/`wait_and_throw()` call sites reachable from the FA path
(`grep -rn -E '(\.|->)(wait|wait_and_throw)\(' ggml/src/ggml-sycl/fattn*.cpp
ggml/src/ggml-sycl/fattn*.hpp` - covers both `.`/`->` call syntax and the `wait_and_throw` name,
which a plain `\.wait(` search misses):

- `fattn-buffers.cpp`'s `ensure_half()` (`qptr->wait()`, only on the grow-and-free branch) is
  provably unreachable during graph capture, not merely unreachable for this scenario's route:
  `ggml_sycl_graph_prepare_fattn_buffers()` pre-grows the K/V scratch buffers to the max
  `ggml_nelements()` over every `FLASH_ATTN_EXT` node in the *same* cgraph before
  `begin_recording()`, using the identical formula `launch_fattn()` uses at dispatch
  (`ggml/src/ggml-sycl/ggml-sycl.cpp:5906-5933`). Pre-grow runs unconditionally for every
  graph-taken `ggml_backend_sycl_graph_compute()` call, and buffer capacity only grows, never
  shrinks, so `ensure_half()`'s `capacity >= need_bytes` fast path is guaranteed to hold for any
  node in that graph regardless of K/V type.
- `fattn-onednn.cpp`'s `stream->wait_and_throw()` is gated on `ggml_sycl_info().device_count >
  1`; `check_graph_compatibility()` already restricts graphs to a single device
  (`ggml/src/ggml-sycl/ggml-sycl.cpp:5867-5871`), so that wait and graph recording are mutually
  exclusive by construction, independent of KV type or which profile flags are set.

Both are structural (proved from the pre-grow/gate code, not just "not hit by this test"), so no
further call site was fixed beyond the four `launch_fattn()` profile waits above.

## Not claimed

- Not a full graphs-enablement promotion: `GGML_SYCL_ENABLE_GRAPH` stays default-off per
  standing decisions; this fix only removes one specific crash blocking correctness work under
  that flag. No paired A/B campaign was run on graphs-on throughput or latency.
- Only one crashing configuration was reproduced and re-verified (Mistral, q8_0/q8_0
  quants-first, d=16384). Other type/depth/model combinations under
  `GGML_SYCL_FA_PROFILE=1 GGML_SYCL_ENABLE_GRAPH=1` were not swept.
- The `graph_recording` flag is not thread-safe beyond the existing single-queue-per-context
  assumption already made throughout this backend; multi-device graph recording
  (`ggml_sycl_info().device_count > 1`) is already disabled by `check_graph_compatibility()`
  before this code path is reached.
- Did not audit non-FA ops for the same class of profile/debug instrumentation calling
  `wait()` unconditionally; only the FA path implicated by this crash was checked.

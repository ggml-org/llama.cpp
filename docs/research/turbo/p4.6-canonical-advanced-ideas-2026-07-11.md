# P4.6 canonical-source audit for advanced KV ideas - 2026-07-11

This audit maps the five advanced ideas carried in the workspace `r1.md` notes
to canonical sources and the current `turbo-sycl-opt` code. It distinguishes
published mechanisms from project-local policies. Moving engineering notes and
all quantitative claims derived from TheTom material remain `[UNVERIFIED]`

and QJL venue-history claims are also `[UNVERIFIED]`; this audit does not use

**Audit provenance.** The repository source audited here is the immutable tree

## Asymmetric K/V

**Canonical source.** KIVI (arXiv:2402.02750, ICML 2024) quantizes K and V to
two bits with different quantization axes. SKVQ (arXiv:2405.06219) combines a
two-bit K cache, approximately 1.5-bit V cache, and retained sliding-window
tokens. AsymKV (arXiv:2410.13212, COLING 2025) selects distinct K/V
configurations by layer. These works support K/V asymmetry in general; none
derives this fork's GQA threshold or exact type rewrite.

**Mechanism.** The literature preserves different information in K and V by
assigning different quantization axes, precisions, retention policies, or
layer-wise configurations. This is broader than simply making K one existing
GGML type and V another.

**Current code seam.** `src/llama-kv-cache.cpp:136-171` implements a
project-local auto-asymmetric policy. When symmetric turbo K+V is requested,
the model's GQA ratio is at least 6, and `TURBO_AUTO_ASYMMETRIC` is not set to
`0`, it upgrades K to `q8_0` while retaining the requested V type.

**Disposition.** **ALREADY SHIPPED / PROJECT-LOCAL POLICY.** No port task is
needed. The literature supports the theme of asymmetry, not the exact
`GQA >= 6` heuristic.

**Falsifier / GO conditions.** Treat the current policy as falsified if pinned,
backend-gated model evidence shows the rewrite worsens quality or capacity at
its target GQA ratios. Any threshold or type-policy change requires a separate
multi-model quality study with the effective post-policy K/V types recorded.

## Boundary V

**Canonical source.** KVQuant (arXiv:2401.18079) provides broad support for
per-layer sensitivity-aware KV formats. The exact first-two/last-two policy
comes from a moving, non-peer-reviewed TheTom engineering document and is
`[UNVERIFIED]` until pinned to an exact commit SHA.

**Mechanism.** Boundary V assigns a higher-precision V format to selected
boundary layers and a smaller format to middle layers, attempting to recover
quality while retaining most of the capacity benefit.

**Current code seam.** `src/llama-kv-cache.cpp:322-382` implements adaptive
modes 5, 6, and 7. Mode 7 assigns `q8_0` V to the first two and last two layers
and `turbo2` V elsewhere. With no environment override, turbo2 V and at least
eight layers auto-enable mode 7. The selector at `:333-348` is currently a
function-local `static const`; its process-lifetime defect is fixed separately
under P4.6a rather than changing this policy.

**Disposition.** **ALREADY SHIPPED / PROJECT-LOCAL.** This is not claimed as a
paper-faithful KVQuant implementation. The exact 2+2 policy remains project
policy.

**Falsifier / GO conditions.** Revisit layer selection only if a pinned,
architecture-diverse quality study shows that modes 5 or 7 fail their intended
quality/capacity tradeoff. That study must record effective per-layer types and
must remain separate from the process-lifetime correctness fix.

## Sparse V

**Canonical source.** The current proposal comes from a moving,
non-peer-reviewed TheTom Metal engineering note. Its source and quantitative
claims are `[UNVERIFIED]` until pinned to an exact commit SHA.

**Mechanism.** The Metal note skips V dequantization for positions whose
materialized post-softmax attention weights fall below a threshold.

**Current code seam.** No sparse-V implementation exists in the SYCL backend.
The VEC kernel in `ggml/src/ggml-sycl/fattn-vec.hpp:298-367` computes online
softmax: it updates the running maximum, exponentiates the current tile,
rescales the prior normalization sum and V accumulator, and then continues V
accumulation. In particular, `:348-365` rescales both `KQ_sum` and `VKQ` after
a new maximum. An interim weight is therefore not a final normalized weight;
a literal post-softmax threshold copied from a materialized-softmax kernel is
unsound in this dataflow.

**Disposition.** **PARK `[UNVERIFIED ON SYCL/A770]`.** No kernel spike is
created.

**Falsifier / GO conditions.** GO requires (1) a valid error bound for gating
within online softmax, (2) a CPU/full-attention oracle with adversarial
late-maximum logits, (3) a harness extension covering those cases, (4) an Arc
profile showing long-context V dequantization is the bottleneck, and (5)
quality within the project's cosine and magnitude bands. Evidence that the
interim-weight gate can exceed those bounds kills the proposal.

## TriAttention

**Canonical source.** Mao et al., arXiv:2604.04921v1, with the official
Apache-2.0 repository `WeianMao/triattention`. It is a real preprint; this audit
does not infer peer-review status beyond the pinned preprint version.

**Mechanism.** TriAttention uses pre-RoPE Q/K concentration calibration, a
trigonometric importance approximation, and fixed-budget KV-token eviction.
Its optimization changes which cached tokens survive.

**Current code seam.** No llama.cpp or SYCL port exists in this fork. The
relevant integration surface would be KV-cache lifecycle and eviction rather
than the quantized V dequantization loop: cache ranking, token bookkeeping,
calibration state, positional semantics, and full-attention baselines would all
be new design work. It is orthogonal to the existing turbo codec.

**Disposition.** **PARK - no demonstrated demand and no llama.cpp/SYCL port.**
No implementation task is created.

**Falsifier / GO conditions.** GO requires a real fixed-budget,
long-reasoning workload, model-specific calibration, an exact full-attention
quality baseline, and a separate cache-lifecycle design task with a
source-complete implementation review and oracle-backed validation. Absent
that workload, a port would be mechanism-first work without a product case.

## QJL

**Canonical source.** Zandieh, Daliri, and Han, arXiv:2406.03482v2, with
Apache-2.0 reference code at `amirzandieh/QJL`. Venue-history claims are
`[UNVERIFIED]` and are not used here.

**Mechanism.** Canonical QJL uses a dense Gaussian Johnson-Lindenstrauss
projection, one-bit signs, and an unbiased inner-product estimator with the
associated residual metadata.

**Current code seam.** The active fork format is not QJL. In
`ggml/src/ggml-common.h:298-310`, `TURBO4_USE_4BIT` defaults to 1 and selects a
16-centroid, nibble-packed format with no QJL residual. The active SYCL codec
in `ggml/src/ggml-sycl/turbo-quants.hpp:39-50,158-166` uses fixed centroid
lookup, while `src/llama-kv-cache.cpp:626-640` prepares fixed Walsh-Hadamard
rotation matrices. SYCL kernels read no residual norm/sign fields and implement
no dense-Gaussian JL estimator. Legacy conditional/reference code and comments
that retain the historical name do not make the compiled default SYCL path a
QJL implementation.

**Disposition.** **KILL the `r1.md` "preserve current QJL" premise; PARK a
paper-faithful implementation.** There is no active QJL mechanism to preserve
in the SYCL turbo4 path.

**Falsifier / GO conditions.** A paper-faithful port proceeds only if QJL
fidelity is an explicit goal. It must independently specify dense-Gaussian
versus structured-transform theory, residual layout, estimator, memory
traffic, capacity cost, and Arc device cost. A source-complete active kernel
that consumes the canonical residual metadata and matches the estimator would
falsify the current "not implemented" mapping.

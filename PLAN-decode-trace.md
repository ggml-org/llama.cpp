# PLAN: per-action decode trace for Kimi-K3 expert streaming (v3)

Branch `kimi-k3-expert-stream`, worktree `llama.cpp-master`. Status: v3 after review round 2 (see Review history).

## 1. Requirement (user, verbatim)

"I need to have profiling functionality for every action, for example when weights are loaded into cache memory,
a timestamp before and after the load, when it's issue and when it's end. For example a matrix op (assuming matrix
execution does not batch) before launching kernel to GPU (or CPU) and when GPU return activation back? All action
shall have a tag with layer, expert and token id. Let's do that for the decode part first (when output token is
generated); for the prompt part, I have no idea right now, so let's wait."

Scope: decode graphs only (ubatch of <= `LLAMA_TRACE_MAX_BATCH` tokens, default 1). Prompt batches and `-np > 1`
batches are not traced (state SUSPENDED, section 6).

## 2. Facts the design relies on (verified in code)

- Decode = 1 token per graph (`llama_context::decode` llama-context.cpp:1856 -> `process_ubatch` :1542 -> `graph_compute` :2772). Decode does NOT synchronize at its end (`//synchronize();` :2259): logits are read with `ggml_backend_tensor_get_async` (:2100) and the wait happens later in `llama_context::synchronize` (:906, called from `llama_get_logits*`). `output.weight` lives on CUDA0 (kimi-k3.cpp:63, layer-less tensors go to the GPU), so the last split of every decode graph is a GPU split and that final wait is a GPU wait. The generated token comes from `llama_sampler_sample` (src/llama-sampler.cpp:895), after the logits wait.
- Node names carry the layer: `graph_get_cb` formats `"%s-%d"` (llama-context.cpp:3109): `ffn_moe_gate-12`, `ffn_moe_up-12`, `ffn_moe_down-12` are the three MUL_MAT_ID outputs of layer 12 (Kimi-K3 has separate gate/up tensors: 3 MUL_MAT_ID x 92 MoE layers = 276 per token). Weights: `blk.12.ffn_up_exps.weight`.
- CPU compute: `ggml_graph_compute_thread` (ggml-cpu.c:3246) runs each node on all threads with a barrier after every node except the last; `ggml_compute_forward_mul_mat_id` (:1642) loops `cur_a` over used experts; for decode (one row per expert) `nchunk0 = nth`, so EVERY thread computes a chunk of EVERY used expert. Tiled path per expert too (:1812). Expert ids = `dst->src[2]`; `ne11 == n_ids`, so used experts <= min(n_as, ids->ne[0]*ids->ne[1]). `ggml_cpu_extra_compute_forward` (repack/AMX buffers, :1891) bypasses this function. `struct ggml_threadpool` (ggml-cpu.c:485) is private to ggml-cpu; `ggml_cplan` is public ABI.
- Work size for MUL_MAT_ID is computed in `ggml_graph_plan` (ggml-cpu.c:3038); plan and compute can be separate calls (`graph_plan_create` / `graph_plan_compute`, ggml-cpu.cpp:130, 162). `cplan->work_data` is reused by the next node: nothing may write into it after the node's barrier.
- Expert I/O issue points: `ggml_cpu_moe_prefetch_piece` (ggml-cpu.c:1570, 2 MiB pieces; `ggml_cpu_mul_mat_id_prefetch` :1583 hands piece k to thread k % nth, so the two pieces of a slice are usually issued by different threads) and `llama_moe_predictor::prefetch_expert` (llama-moe-predict.cpp:479; a LOW slice calls `drain_high()` between its pieces, :494-496, so HIGH issues nest inside a LOW slice). The windowed path `ggml_cpu_moe_window_issue` (:1621) only runs when the used experts exceed the window, i.e. prompt batches (SUSPENDED): it is not traced. WILLNEED is asynchronous and the kernel gives no completion signal; the kernel caps one WILLNEED at max(ra_pages, io_pages) = 16 MiB here, so the 2 MiB pieces are never split.
- Measured on this box (reviewer C): `mincore` on a cached unmapped 2 MiB range 19.6 us (22 us with I/O in flight), on a mapped range 2.5 us; cold WILLNEED on 2 MiB blocks the issuing thread 648 us, cached 19.7 us; a WILLNEED-covered touch with I/O still in flight shows majflt 0 / minflt 517 and 33.6 ms off-CPU, an uncovered touch one majflt per 4 KiB page; `getrusage(RUSAGE_THREAD)` 0.48 us but its utime/stime are tick-sampled (1 ms, no nohz_full), so per-expert CPU time uses `clock_gettime(CLOCK_THREAD_CPUTIME_ID)` (ns resolution, ~30 ns); `/proc/self/task/<tid>/io` 3.5 us; `cachestat` counts in-flight folios as cached (unusable); `perf_event_paranoid = 4` (no perf/eBPF without root). IQ1 slices: gate/up 2,150,400 B, down 3,612,672 B -> 2 pieces per slice, 6 per expert; 28 logical CPUs, 14 compute threads + predictor worker, no idle spare CPU.
- GPU: `ggml_cuda_graph_evaluate_and_capture` (ggml-cuda.cu:4449) launches node by node (fusion `ggml_cuda_try_fuse` :4607; multi-stream `GGML_CUDA_GRAPH_OPT` sets `curr_stream_no` per node :4548-4571) unless a CUDA graph is replayed (:4659). `ggml_backend_cuda_graph_compute` (:4684) decides `use_cuda_graph` / `cuda_graph_update_required` inside `#ifdef USE_CUDA_GRAPH` (:4693-4729), refreshing node properties.
- Scheduler: `ggml_backend_sched_compute_splits` (ggml-backend.cpp:1865); `ggml_backend_sched_copy_input` (:1823): `ggml_backend_event_wait` (:1842) is a device-side wait (instant for the host), the fallback `ggml_backend_synchronize(input_backend)` + `ggml_backend_tensor_copy` (:1853-1861) is where the host actually waits for the GPU and copies. `cb_eval` syncs after every node (:1927): not used.
- Decode layout (run-server.sh): layers 0-10 dense on CUDA0, 11-92 dense on CPU (eager, pinned host memory: no I/O events for dense weights), all experts on CPU, lazily mmapped. Layers 1-10 alternate GPU/CPU splits, plus the final output split on CUDA0: ~26 splits per token.
- Residency test pattern: tests/test-moe-prefetch.cpp (`mincore`, mmapped weights file, MUL_MAT_ID graph, re-exec with env).

## 3. Event model

One fixed-size record (96 bytes) written by the acting thread: t0_ns, t1_ns (CLOCK_MONOTONIC; t1 = 0 for instants), type, detail (source / flags), backend (0 = CPU, 1.. = device index interned at start), tid (CPU worker index for compute threads, else OS tid; predictor/poller/writer/sampler get named tracks), step (traced decode counter; -1 in IDLE), token, pos, layer (-1 unknown), expert (-1 n/a), op, bytes, aux, aux2, name[32].

| type | span | emitted by | tags / notes |
|---|---|---|---|
| TOKEN | batch begin -> `decode` returns | llama-context decode loop | token/pos from `ubatch.token[0]`/`pos[0]`; args get `token_out` stamped from the following SAMPLE |
| SYNC (output) | the logits wait in `llama_context::synchronize` (:906) | under `enabled()`, track sched, step = last TRACED step, detail = output | t0 >= TOKEN.t1; this is when the last GPU split (output.weight on CUDA0) returns; `trace_report` adds it to the token wall time |
| SAMPLE | `llama_sampler_sample` t0..t1 | llama-sampler.cpp:895 | aux = sampled token, stamped into the most recent TRACED token only if no `batch_begin` happened since |
| XFER | `ggml_backend_tensor_set/get(_async)` while TRACED | ggml-backend.cpp:405-490 | detail = input/output, bytes, name (inp_tokens, inp_pos, KQ_mask, result_output) |
| SPLIT | one scheduler split | compute_splits | backend, n_nodes, layer of first node |
| COPY | the sync `ggml_backend_tensor_copy` of a split input | copy_input :1861 / :1836 | bytes, name, detail = sync; async copies (`cpy_tensor_async` :1854) are COPY instants with detail = async |
| SYNC | host blocked in `ggml_backend_synchronize` / `event_synchronize` | copy_input :1855-1860, compute_splits :1879-1883 | backend; "the GPU returns the activation" |
| OP_CPU | node compute incl. the trailing barrier; last node: t1 after the final barrier (:3312) | `ggml_graph_compute_thread`, worker 0 | op, name, layer; detail = fused node count; one event per fused group |
| OP_GPU | host launch t0..t1 (aux) plus device t0..t1 from a cudaEvent pair | ggml-cuda evaluate loop | one per fused group; aux2 = stream no |
| EXPERT | compute of one expert slice in MUL_MAT_ID, over threads: min t0 .. max t1 | worker 0 after the node barrier, from per-thread wdata slots | expert = `cur_a`, bytes = `nb02`, aux = sum over threads of (wall - thread CPU time) = stall ns, aux2 = t_first_touch (first-arriving thread) |
| EXPERT_THREAD | same per thread (detail level 2) | each thread | aux = wall - thread CPU time, aux2 = minflt/majflt deltas from one `getrusage(RUSAGE_THREAD)` pair (Linux only) |
| EXPERT_RESIDENCY | instant, t = mincore time | poller, from a request posted by the first-arriving thread | key (step, layer, expert, tensor); aux = resident pages / total, aux2 = sample_delay_ns = t_mincore - t_first_touch; joined to EXPERT by key in writer/report |
| IO_ISSUE | one `posix_madvise` piece, t0..t1 (it blocks up to ~650 us cold) | prefetch_piece, prefetch_expert | layer/expert/tensor explicit, piece index, detail = prefetch / predict_high / predict_low + guess rank + duplicate flag, aux = cookie, aux2 = `read_bytes` delta around this piece |
| IO_RESIDENT | instant | poller, or the issuer when the piece's `read_bytes` delta is 0 (cached=true) | same cookie; aux = t_prev_poll, aux2 = t_this_poll (true uncertainty window); at token end unresolved ranges get detail = unresolved, aux = resident fraction |
| PREDICT | `on_layer` t0..t1 | llama-moe-predict.cpp on_layer | layer = il, bytes = n guesses; exactly 92 per token |

Stall metric: every thread computes a chunk of every used expert, so each thread records per expert {t0, t1, cpu0, cpu1} with `clock_gettime(CLOCK_MONOTONIC / CLOCK_THREAD_CPUTIME_ID)` (4 reads, ~120 ns); off-CPU time = (t1 - t0) - (cpu1 - cpu0) = page-fault / I/O wait plus preemption (the poller and writer share hyperthread siblings with the compute threads; stated in the metadata). Level 2 adds minflt/majflt from one `getrusage(RUSAGE_THREAD)` pair. Per-fault latency is not observable without root (perf_event_paranoid = 4).

"Load end" for WILLNEED, three mechanisms, all per piece:
1. Already cached at issue (~73% of hits): the issuer snapshots `/proc/self/task/<tid>/io` `read_bytes` immediately before and after each `posix_madvise` (3.5 us each). Delta 0 -> IO_RESIDENT emitted immediately with cached=true, no poller entry. Per piece is required: the compute-thread prefetch keeps its k % nth round-robin (the two pieces of one slice are issued by different threads), and a predictor LOW slice nests HIGH issues between its pieces (drain_high). The writer merges the two piece records of a slice into the level-1 slice span (cached iff both deltas are 0; issue t0 = first piece t0, t1 = last piece t1); level 2 keeps the pieces.
2. Otherwise the piece goes to the poller: dedupe by (addr, len) first (a second issuer gets detail = duplicate and the original cookie, no new entry); the poller probes the tail page, then the full range, every `LLAMA_TRACE_POLL_US` (default 1000) and records the actual poll timestamps around the transition. Budget: up to ~100 pending ranges x 20 us = 2 ms per poll at 1 ms cadence: the poller can use most of one logical CPU during heavy I/O, shared with compute hyperthreads (28 logical, 14 compute + predictor + poller + writer); this is part of the measured overhead. If a poll exceeds the interval it doubles and a metadata event records it.
3. Residency at compute start: a shared per-expert `atomic_int` flag (its own wdata carve-out of min(n_as, n_ids*ne11) ints, reset by worker 0 before the barrier) picks the first-arriving thread of expert `cur_a`; that thread pushes {step, layer, expert, tensor, slice addr/len, t_first_touch} into a lock-free MPSC ring (compute threads never take a mutex; ring full -> counted drop) and wakes the poller immediately (eventfd / futex). The poller runs `mincore` and emits its own EXPERT_RESIDENCY event with sample_delay_ns; nothing is ever written back into `work_data`. Target: sampled within ~50 us of first touch (E2E: median sample_delay < 200 us, not-sampled < 1%). `mincore` needs the mapping readable by the caller; the file is checked once (`st_uid == geteuid() || access(W_OK)`) and a metadata field flags residency as invalid otherwise.

## 4. Output format and buffering

- Chrome Trace Event JSON for ui.perfetto.dev: `[` + one event per line; a truncated file still loads. First record is metadata: model, n_threads, GPU layers, the full `LLAMA_TRACE*` config, cuda_graphs_disabled_while_traced, poll interval, residency validity, stall-metric caveats; values known only at close (drop count, ring drops, poller-interval adaptations) are fixed-width zero-padded fields rewritten in place at close.
- Non-overlapping per-thread spans are "X" events: OP_CPU, OP_GPU (device / launch), SPLIT, COPY, SYNC, XFER, SAMPLE, PREDICT, TOKEN, and IO_ISSUE on the ISSUING thread's host track (worker N or predictor). EXPERT and issue->resident spans overlap on a track, so they are async "b"/"e" events with `id` = cookie / expert key and `cat` = expert / io: the I/O track carries only the b (at issue t0, `issue_dur` in args) .. e (resident) span. Tracks: pid 1 host (worker 0..n-1, sched, predictor, poller, sampler), pid 2 CUDA0 (device, launch), pid 3 expert compute (tid = gate/up/down), pid 4 expert I/O (tid = tensor x source). `args`: step, token, pos, layer, expert, name, op, bytes, backend, resident_frac, sample_delay_ns, stall_ns, source, rank, piece, cached, duplicate, unresolved, issue_dur, layer_inferred.
- Layer tag parsed by the writer from `-<il>`, `blk.<il>.`, `_l<il>`; nodes without a tag inherit the last known layer of their track with `layer_inferred: true`.
- Buffering: each emitting thread owns a chain of 64 KiB chunks (680 events) from a pool; append = fill, release-store count; the writer thread scans registered chunks every 100 ms, acquire-loads counts, serializes into a 1 MiB buffer, `fwrite`s, recycles. No lock on the emit path; the pool mutex once per chunk. Cap `LLAMA_TRACE_BUFFER_MB` (default 64); overflow drops and counts (never silent). Threads that never emitted are skipped.
- Config (llama_context constructor): `LLAMA_TRACE=<path.json>`, `LLAMA_TRACE_TOKENS=N` (default 16; 0 = unlimited; file closed after N traced tokens), `LLAMA_TRACE_SKIP=M` (default 1: the first decode token after a prompt pays the prompt's cold state; SKIP counts decode-size batches, TOKENS traced ones), `LLAMA_TRACE_MAX_BATCH` (1), `LLAMA_TRACE_DETAIL` (1 | 2), `LLAMA_TRACE_POLL_US` (1000), `LLAMA_TRACE_BUFFER_MB` (64). run-server.sh: `TRACE=<path>`. `ggml_trace_start` is refcounted; `ggml_trace_stop` joins poller and writer before the model is unmapped and tolerates ENOMEM from `mincore`.
- Volume per token, level 1: OP_CPU ~6k, OP_GPU ~0.6k, SPLIT/COPY/SYNC/XFER ~0.2k, EXPERT 4416 + EXPERT_RESIDENCY 4416, IO_ISSUE 4416 prefetch slice spans + ~2-4k predictor, IO_RESIDENT one per non-duplicate issue, PREDICT 92, SAMPLE 1, output SYNC 1: ~26k events, ~5 MB JSON (~180 B/event). Level 2: 8832 prefetch pieces, 14 x 4416 EXPERT_THREAD: ~95k events, ~17 MB/token. TOKENS=16 -> 80 MB / 270 MB. Write rate at 0.5 tok/s ~2.5 MB/s.

## 5. Overhead

- Off: `LLAMA_TRACE` unset, `ggml_trace_start` never called; hooks are guarded by one relaxed atomic load read once per graph: on the CPU into a field of the private `struct ggml_threadpool` (ggml-cpu.c:485; `ggml_cplan` is public ABI and stays unchanged), once per `ggml_backend_cuda_graph_compute`, `compute_splits`, `prefetch_expert`. No clock reads, no allocation, no threads.
- Two predicates: `ggml_trace_active()` true only in TRACED (compute, copy, GPU hooks: prompt batches pay nothing and keep CUDA graphs); `ggml_trace_enabled()` also true in IDLE, used by the predictor I/O hooks (late LOW hints, step -1) and by the output SYNC in `synchronize`.
- On, per token: ~26k clock reads (<1 ms); per-expert CPU-time bookkeeping: every thread does all 4416 experts x 4 clock reads (~0.5 ms per thread, ~0.5 ms wall; with level-2 getrusage pairs ~4 ms wall); 2 x 8832 `read_bytes` snapshots at 3.5 us on the issuing threads (~62 ms CPU over 14 threads, ~4.5 ms wall); ~1200 `cudaEventRecord` (2-4 ms); CUDA graphs off for layers 0-10 and the output split (3-6 ms); poller up to one logical CPU during I/O (hyperthread contention, counted in the stall metric). Estimate ~15-25 ms of a ~1900 ms token (~1%), level 2 ~3%; target < 5%, verified by the protocol in section 7.
- GPU timing: per launch group two `cudaEventDefault` events from a growable per-context pool (cap 16k, drop counter) recorded on the node's current stream; start event recorded before `ggml_cuda_try_fuse`, stream no kept with the pending record. Nothing waits inside the token. Resolution runs only on the thread that calls `batch_begin` / `trace_stop` (never the writer): pairs whose end event `cudaEventQuery` == success are resolved; an anchor event is recorded only when ALL pending end events are complete (else deferred to the next call), synchronized (its wake-up shifts device times by a constant ~5-20 us, stated in metadata), host ns taken; device_ns = anchor_host_ns - elapsed(e_i, anchor). `cudaEventElapsedTime` is never called on an unfinished event. The flush callback is registered at backend init; `~ggml_backend_cuda_context` resolves the already-complete pairs, unregisters, then destroys pool and pending events.
- CUDA graphs: the bypass sets `use_cuda_graph = false` and `cuda_graph_update_required = false` when `ggml_trace_active()`, after the `#ifdef USE_CUDA_GRAPH` block (:4729), so node properties / uid still refresh and the captured instance stays valid for untraced batches. With `GGML_CUDA_GRAPH_OPT` the direct path runs multi-stream; events on the node's stream are device-wide timestamps.

## 6. Where the hooks live

ggml must not depend on llama: a small ggml-base module with a C API, called from ggml-cpu, ggml-cuda, ggml-backend, llama.

1. `ggml/include/ggml-trace.h`, `ggml/src/ggml-trace.cpp` (C++ inside, `extern "C"` API, ggml-base, ggml/src/CMakeLists.txt:192): `ggml_trace_start/stop` (refcounted), `ggml_trace_active()`, `ggml_trace_enabled()`, `ggml_trace_batch_begin(n_tokens, step, token, pos)` (TRACED or SUSPENDED; `-np > 1` SUSPENDED) / `ggml_trace_batch_end()` -> IDLE, `ggml_trace_now_ns()`, `ggml_trace_emit(ev)`, `ggml_trace_io_issue(addr, len, source, rank, layer, expert, name, piece, t0, t1, read_bytes_delta)` (dedupe, cached fast path, poller entry; returns cookie), `ggml_trace_residency_request(step, layer, expert, name, addr, len, t_first_touch)` (MPSC ring + wake), `ggml_trace_register_flush / unregister`, `ggml_trace_backend_id(name)`, `ggml_trace_stamp_token_out(token)`, `ggml_trace_read_bytes()`. Poller, `mincore`, `/proc`, `CLOCK_THREAD_CPUTIME_ID` and `getrusage(RUSAGE_THREAD)` are Linux-only (`#ifdef`); elsewhere the residency and stall fields are absent and the metadata says so.
2. `ggml/src/ggml-cpu/ggml-cpu.c`: `ggml_graph_compute` reads the predicate once into the threadpool; worker 0 emits OP_CPU (one per computed node or fused group; last node after the final barrier) and, for MUL_MAT_ID, EXPERT from the per-thread slots after the barrier (read-only; `work_data` is never written after the barrier). `ggml_graph_plan` reserves unconditionally for MUL_MAT_ID: per-thread slots `nth x min(n_as, n_ids*ne11) x {t0, t1, cpu0, cpu1, minflt, majflt}` (14 x 16 x 48 B = 11 KB; worst case ~155 KB) plus the shared first-arrival flags `min(n_as, n_ids*ne11) atomic_int`; no trace-state coupling between plan and compute; the hook bounds-checks `params->wsize` and skips EXPERT events if the slots are missing. The carve-out moves into a helper shared with the flush. `ggml_cpu_moe_prefetch_piece` wraps each madvise with read_bytes snapshots and emits one IO_ISSUE per piece; `ggml_cpu_moe_window_issue` is untouched (prompt only).
3. `ggml/src/ggml-backend.cpp`: SPLIT, COPY, SYNC in `compute_splits` / `copy_input` as placed in section 3; XFER in `ggml_backend_tensor_set/get(_async)`.
4. `ggml/src/ggml-cuda/ggml-cuda.cu`: event pool + pending list in `ggml_backend_cuda_context`; OP_GPU records in the evaluate loop; lazy resolution + anchor in the flush callback; bypass after the `#ifdef` block; destructor order as in section 5.
5. `src/llama-moe-predict.cpp`: `prefetch_expert` emits per-piece IO_ISSUE with source HIGH/LOW and guess rank (router / popularity position, carried in `work`); `on_layer` -> PREDICT span.
6. `src/llama-context.cpp`: constructor reads `LLAMA_TRACE*`, `ggml_trace_start`; decode loop wraps `process_ubatch` and the output read-back with `batch_begin/end` (TOKEN end = `decode` return; GPU pairs resolve at the next `batch_begin`); `synchronize()` (:906) emits the output SYNC under `enabled()`; destructor `ggml_trace_stop`. `src/llama-sampler.cpp:895`: SAMPLE span + `ggml_trace_stamp_token_out`.
7. `kimi-k3/run-server.sh`: `TRACE` passthrough; `kimi-k3/tools/trace_check.py` (section 7) and `kimi-k3/tools/trace_report.py` (per token and per layer: CPU/GPU op time, expert compute time, residency at compute start mean/min and count not resident, sample_delay median, issue->resident latency median/p95 per source, I/O wait = sum of stall ns, SYNC wait incl. the output SYNC, COPY/XFER bytes, predictor hit rate per source and rank, and the token wall time = TOKEN span + output SYNC reconciled with the unaccounted remainder).

## 7. Tests (intent-based assertions)

Unit test `tests/test-trace.cpp` (LINK ggml, Linux, CTest; nlohmann/json.hpp): MUL_MAT_ID graph with weights in a plain CPU buffer whose data is an mmapped temp file at an unaligned offset (repack/extra path never applies), n_as = 8, n_used = 2, 1 token, ids = {3, 5}, nb02 > 2 MiB (2 pieces per slice), names `ffn_moe_up-7` / `blk.7.ffn_up_exps.weight`, `GGML_CPU_MOE_PREFETCH=1` via re-exec as test-moe-prefetch does. Before the run expert 5's slice is evicted with `posix_fadvise(DONTNEED)` and expert 3's slice is touched (hot). Asserts:
- exactly 1 TOKEN (step 0, token/pos as passed, `token_out` stamped), all events inside carry step 0, none -1; OP_CPU count == nodes that are computed (excluding empty ops, nodes without GGML_TENSOR_FLAG_COMPUTE, and nodes absorbed by `ggml_cpu_try_fuse_ops`; one per fused group), the MUL_MAT_ID one with t0 < t1 and layer 7;
- EXPERT: exactly one for each of {3, 5}, none for the other 6; layer 7; bytes == nb02; OP.t0 <= EXPERT.t0 < EXPERT.t1 <= OP.t1; stall_ns >= 0; exactly one EXPERT_RESIDENCY per EXPERT with the same key, resident_frac in [0, 1], sample_delay_ns >= 0; with prefetch disabled (second re-exec) resident_frac(5) < 1.0 and stall(5) > stall(3);
- IO_ISSUE (prefetch): layer 7; level 2 exactly 2 per used expert with piece 0/1 and bytes == page-rounded size computed from the actual piece addresses (slice + 1 page per internal boundary), level 1 one merged span per used expert; 0 for unused; t0 <= t1; expert 3's pieces cached=true, expert 5's not cached with IO_RESIDENT.t >= issue t1 (or unresolved); every non-duplicate issue has exactly one IO_RESIDENT with the same cookie (cached, or resolved with t_prev_poll <= t_this_poll, or unresolved) and resolved + unresolved + cached == non-duplicate issued after `ggml_trace_stop`; issuing the same range twice yields detail duplicate with the original cookie and no second poller entry;
- state machine: a 40-token batch produces no OP/EXPERT/IO events (SUSPENDED); an issue in IDLE is recorded with step -1; a SYNC emitted in IDLE carries the last traced step; trace off: no file, both predicates false;
- plan created with the trace off, computed with it on: no out-of-bounds, EXPERT events present; `LLAMA_TRACE_BUFFER_MB=1` with a 200k-event loop: drop count in metadata == emitted - written, file still parses; a full residency ring is counted, never blocks;
- level 2: EXPERT_THREAD count == n_threads x 2, their min t0 / max t1 equal the EXPERT span;
- JSON: loads as an array also when truncated after any line; every event has ts, dur or ph in {i, b, e}, pid/tid, required args. The test runs 3 times; one run under TSAN (`-fsanitize=thread` build when available).

End-to-end (Sonnet tester, coordinated with the user; run-server.sh refuses a second llama process), `kimi-k3/tools/trace_check.py` on `TRACE=/tmp/k3.json LLAMA_TRACE_TOKENS=8 LLAMA_TRACE_SKIP=1`, prompt + `n_predict` 32:
- exactly 8 TOKEN spans with consecutive steps and positions; exactly one output SYNC per TOKEN with t0 >= TOKEN.t1; exactly 1 SAMPLE per TOKEN with SAMPLE.t0 >= SYNC.t1 and SAMPLE.token_out == next TOKEN.token; no step -1 event while a TOKEN is open; no OP/EXPERT/IO events during the prompt batch;
- per token exactly 4416 EXPERT, 16 distinct experts per MoE layer, the same set on gate/up/down; exactly 4416 EXPERT_RESIDENCY (not-sampled < 1%), sample_delay median < 200 us; exactly 92 PREDICT; every EXPERT (l, e) has an earlier IO_ISSUE for (l, e) in the same token;
- exactly 4416 IO_ISSUE source=prefetch slice spans per token at level 1 (8832 pieces at level 2); IO_RESIDENT count == non-duplicate IO_ISSUE count; report prints unresolved count, median/p95 latency per source, predictor hit rate per source and rank;
- OP_GPU for every layer 0..10 and the output split, none for layers 11..92; SYNC/COPY at the layer 1..10 boundaries; XFER input before the first OP of each token and output after the last;
- coverage: OP_CPU (worker 0) + SYNC + GPU split time >= 90% of each TOKEN span + output SYNC; the unaccounted remainder is printed;
- overhead protocol: same prompt, `n_predict` >= 32, order warm -> off -> on -> off, decode tok/s from server timings; on >= 0.95 x mean(off1, off2); additionally counted syscalls x measured per-call cost (section 2) < 5% of the token time;
- the JSON loads in Perfetto `trace_processor` (python `perfetto`): `SELECT count(*) FROM slice` equals the X + b events parsed by the script.

## 8. Risks and open questions

- Poller timestamps are honest (t_prev_poll .. t_this_poll) but 1 ms wide; per-piece NVMe latency (~100 us) is below that. The compute-start residency and the stall metric do not depend on it.
- `read_bytes` is per task and counts only I/O caused by the issuing thread; cross-thread duplicates are handled by the dedupe table.
- The stall metric includes preemption by the poller/writer on hyperthread siblings, not only fault wait.
- WILLNEED gives no guarantee: a range can be evicted between resident and compute; the residency fraction catches it.
- Disabling CUDA graphs for traced tokens changes GPU timing by 3-6 ms; the anchor wake-up shifts device times by a constant ~5-20 us; both in metadata.
- Level 2 volume (17 MB/token); mitigated by TOKENS default 16 and the drop counter.
- Fused groups produce one OP event (first node's name).
- Repack/AMX extra buffers bypass `ggml_compute_forward_mul_mat_id` (no EXPERT events; not the case for mmapped experts).
- Open: `LLAMA_TRACE_MAX_BATCH` default 1 vs 4 (speculative decoding); keep 1. Open: suppress predictor HIGH duplicates at level 1 (~4k events).
- Not in scope: prompt batches (incl. the windowed prefetch), `llama_direct_reader`, GPU prefill, MoE cache.

## 10. Implementation order

1. ggml-trace core: chunks, writer, JSON, state machine, poller (dedupe, cached fast path, residency ring + wake); unit-tested alone.
2. ggml-cpu hooks (OP_CPU, EXPERT with CPU-time stall metric, first-arrival flags, per-piece IO_ISSUE) + llama-context TOKEN / output SYNC + sampler SAMPLE + `tests/test-trace.cpp`.
3. ggml-backend SPLIT/COPY/SYNC/XFER, ggml-cuda OP_GPU with lazy resolution + anchor + bypass.
4. predictor per-piece hooks with rank, launcher `TRACE`, `trace_check.py`, `trace_report.py`, end-to-end run and overhead protocol.

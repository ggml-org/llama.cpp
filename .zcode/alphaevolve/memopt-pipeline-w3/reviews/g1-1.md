- ctest -R test-server-prompt-cache: PASSED (0.30s).

### Critique (soundness, risk, suggested merge)
- Soundness: the dequant helpers are bit-exact ports of dequantize_row_q{2_K,4_0,5_0}_ref.
  The CPU q2_K helper reads d/dmin via raw half pointer (portable across the
  GGML_COMMON_AGGR_* union macro states). The Metal q2_K uses .d/.dmin directly
  (Metal context = anonymous union). Both verified to compile.
- Risk: LOW for the dequant code itself. The q4_0/q5_0 paths are the practical
  ones on Metal. q2_K is correct but Metal-blocked (no quantize_q2_K / set_rows).
- Verdict: **promote as PARTIAL**. The gene's own code is correct and the q4_0
  memory/throughput win is real. The end-to-end paged path is blocked by a
  pre-existing SWA bug (see below), which is out of this gene's scope.

### CRITICAL FINDING: pre-existing paged-attn / SWA bug (not from this gene)
The TESSERA_PAGED_ATTN path produces garbage on gemma-4-12B for ALL KV types
including f16:
  f16 flash (non-paged): coherent ("A key question. A key question. ...")
  f16 paged:             garbage ("A a/વિ a fede1अफ. أي011. ...")
  3.8pct token agreement (80-token greedy) between f16 paged and f16 flash.
Likely cause: gemma uses SWA (sliding-window attention, swa pattern period 6),
and build_tessera_full_page_map does not take is_swa / n_swa - it marks ALL
resident positions as attendable, so SWA layers attend outside the window.
S1's "f16 paged == f16 ref (0/40 tokens)" was on qwen0.5B (no SWA); it does
NOT hold for this SWA model.

RECOMMENDED NEXT WAVE: fix S1's paged path to mask non-window positions for
SWA layers (per-layer SWA-aware page_map, or pass an SWA mask into the paged
op). Once fixed, re-validate S4 q4_0 end-to-end - the quant code is ready.

### Honesty note on KIVI scope
The plan called for "KIVI-style asymmetric 2-bit: per-channel K, per-token V".
True per-channel-K needs a scale buffer indexed by channel with 2-bit values
packed along the token axis - a different memory layout that cannot reuse
ggml_set_rows / standard quant ops, plus a custom quant kernel. That is well
beyond a single 50-min gene. This gene delivers the achievable subset: low-bit
KV via standard K-quants (q2_K/q4_0/q5_0) with tessera's existing Hadamard
rotation as the quality mechanism. The Hadamard rotation is exactly the
"transform-then-quantize" trick (QServe) that makes low-bit KV viable; KIVI's
per-channel-K asymmetry would be an additional refinement on top.
